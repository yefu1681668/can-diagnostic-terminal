# 黑匣子（事件记录器）设计说明

## 1. 目标

把诊断相关关键事件（故障发生、清码、会话切换、解锁、参数修改）持久化到外部 SPI Flash，**掉电不丢**，作为车载 EDR（Event Data Recorder）的教学原型。

## 2. 存储布局（W25Q16，占用前 64KB 中的 16KB）

```
扇区 0 (0x000000): 元数据
  [0..3] magic "BBOX" (0x42424F58)  —— 首次上电识别
  [4..7] 记录计数 s_count (uint32)  —— 上电恢复写指针

扇区 1..3 (0x001000 ~ 0x003FFF): 记录池
  每条记录 16 字节定长，共 768 条
```

### 记录格式（16B）

```
[0]     事件类型 (0x01 故障置位 / 0x02 清码 / 0x03 会话 / 0x04 解锁 / 0x05 改参数 / 0x06 上电)
[1..4]  时间戳 HAL_GetTick() 毫秒（小端）
[5..6]  参数（故障号 / 会话号 / 新参数值）
[7..15] 保留 0x00
```

## 3. 写入策略

- 追加写：`slot = s_count % 768`，直接页编程
- 每写一条都把新计数刷回元数据扇区（先擦后写）——保证任意时刻掉电，重上电都能恢复到"已成功写入的最后一条"
- 写满 768 条后回卷：跨入新扇区的第一条先擦整个扇区

### 为什么这样设计

- Flash 只能"1→0"写、擦除只能整扇区 4KB，所以追加写前必须保证目标区域是擦净的
- 元数据每条都刷是简化做法；真实产品用"日志式双副本元数据 + 掉电安全事务"避免频繁擦元数据扇区

## 4. 已知简化（与真实产品的差距）

| 本项目 | 真实产品 |
|--------|----------|
| 写满整池后擦池重写 | 滚动擦除：先擦下一个扇区再写，无感知回卷 |
| 元数据单副本每条刷写 | 双副本 + CRC + 事务提交 |
| 时间戳 = 上电毫秒 | 带备用电源的 RTC 绝对时间 |
| 无磨损均衡 | 全池轮转 + 磨损计数 |

这些差距在面试里主动讲出来是加分项：说明你知道简化在哪、真实方案是什么。

## 5. 验证方法

```
cmd> fault 1          # 写入 FAULT_SET
cmd> session 3        # 写入 SESSION
cmd> bb               # 导出日志
（拔电，重上电）
cmd> bb               # 日志还在 -> 掉电恢复通过
```
